## 第一阶段：内容编辑 + AI 适配 + 模拟发布

目标：输入一篇文章，生成公众号、知乎、小红书、B站四种预览。

交付内容：

- 统一内容 IR
- 平台 Adapter 接口
- 四个平台 profile
- 多 Agent 编排接口
- 模拟发布任务接口
- 前端编辑、预览、任务看板和账号页面
- 共享素材库和正文素材引用

## 第二阶段：真实发布闭环 ✅（核心已交付）

已接入能力相对明确的平台，形成真实闭环：

- ✅ 公众号草稿、素材上传、人工确认群发
- ✅ B站视频稿件发布、查询、删除
- 🔄 小红书通过 myaibot API 提交笔记，用户扫码完成最终发布（后端 Adapter 已就绪）

已完成交付：

- 公众号：上传素材、创建草稿、提交发布、查询发布状态。
- B站：passport 密码登录保存 Cookie 凭据，支持视频/封面上传、稿件提交、状态查询、删除测试稿件。
- 小红书：通过 `publish-with-upload` 提交标题、正文、图片/视频和封面；需要 API Key、素材公网 URL 和账号上下文。
- 真实发布任务通过 Celery + Redis 异步执行。
- 账号凭据加密保存到 PostgreSQL。
- 数据库结构通过 Alembic 迁移管理。
- 前端：AccountView 账号管理（公众号连接、B站验证码登录/密码登录）、PublishConfirmView 发布确认（统一/独立配置切换）、TaskView 任务看板（状态刷新/草稿发布）。

待补齐：

- 小红书前端账号管理入口和真实联调。
- 发布失败时更细粒度的错误恢复建议。
- 前端对小红书二维码/状态轮询的完整展示。

## 第三阶段：浏览器辅助发布

知乎先做人机协同，小红书可作为 API 发布失败时的备用路线：

- 打开发布页面
- 自动填充标题、正文、图片和标签
- 用户手动处理验证码、风控和最终发布确认

## 第四阶段：Agent 工作流增强

当前已有规则引擎模拟编排 + 内置 MCP 风格工具编排（`adapt-preview`），支持标题/关键词建议、风格改写和多平台适配。后续增强方向：

- Agent 任务规划：根据目标平台自动选择 Agent 链路。
- 合规检查增强：AIGC 标注、版权风险、夸大宣传检测。
- 发布失败智能恢复：分析日志和平台错误，给出修复建议。
- 发布报告自动生成。

## 第五阶段：数据反馈

抓取阅读、点赞、收藏、投币等数据，反哺下一次标题和平台风格建议。
